The loop — a note's life

  1. A reviewer opens the site with ?review=1 and pins a note. It lands here in Under review.
  2. You triage it: 🔧 Fix (optionally typing an instruction for Claude) → it moves to Scheduled. Or Park / Resolve it.
  3. Click 🤖 Fix with Claude on the site's group → a ready-made prompt is copied. Paste it into Claude Code (or just type /fix-queue <site> there).
  4. Claude builds the fixes on a branch and opens a GitHub PR. Claude never merges.
  5. The PR appears in 🔀 Builds above. Open it → side-by-side before/after → Approve & merge, or 🚩 Flag with a reason (the note re-queues and Claude retries against your reason).
  6. On merge the built HTML lands on your clipboard with the GHL paste checklist. Claude then marks the notes resolved — the reviewer sees a green pin.

Get the GitHub token (the 🔑 button) — one time, ~2 minutes

  1. Open github.com/settings/personal-access-tokens/new (Settings → Developer settings → Fine-grained tokens).
  2. Token name: review-os-dashboard. Expiration: 90 days is fine.
  3. Repository access: "Only select repositories" → tick your client repos (today: website-review, pixeldust-lovedust).
  4. Permissions → Repository permissions: set Contents = Read and write and Pull requests = Read and write. Nothing else.
  5. Generate, copy the github_pat_… string, come back here, click 🔑, paste.

It's stored only in this browser. When it expires the Builds panel goes quiet — make a new one and paste again. Type clear in the 🔑 box to remove it.

Links & codes

  1. Reviewer link (send to a client): the live page + ?review=1
  2. Owner mode (your triage tools on the page itself): open once with &owner=1
  3. Client portal: Deliverables panel → 🔗 client portal link — their password is pds
  4. This dashboard: your code is the one you set — it's remembered per browser
  5. New site on the dashboard: type its board key above, or open dashboard.html?add=<board>

Wire a brand-new client (nothing is copied — five pointers)

  1. Create their GitHub repo (site source lives there, never in the tool's repo).
  2. Add a clients row in Supabase with repo = 'owner/name' → their PRs appear in Builds.
  3. Set the board key: WR_CONFIG.projectKey in their page (GHL sites: paste ghl-review-loader.html into Settings → Tracking Code → Body once).
  4. Map the board in reviews/config.json so sync.mjs writes feedback into their repo.
  5. Add the board here with ?add=<board>.
